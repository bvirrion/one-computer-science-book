## Book-wide decisions

- **Target**: ~470 pp, 32 chapters, ~14.5 pp each (12 exercises 4★/5★★/3★★★ and a 22–28-question weekend
  problem in Parts I–IV ending on a named, quantified result; ch. 32 is the project: milestones, no problem).
- **Languages**: Part I in **Rust** (one compiler for Moor, `sources/book5/MOOR.md`, built module by module;
  each later chapter includes earlier modules with `#[path = "../../NN-slug/listings/x.rs"] mod x;`, so no
  module is ever copied; a module is frozen when its chapter closes). Part II in **C** (kernel-side
  mechanisms simulated in user space) with RISC-V assembly on `code/shared/rv/` for the context switch and
  trap-and-emulate; Python for the policy simulators where memory is not the point. Parts III–V in
  **Python** (stdlib; hypothesis in tests), Part IV storage structures in Python over real 4 KiB page files;
  ch. 24 in C and Rust (threads); ch. 31 in C; ch. 32 in Rust.
- **Running the compiler in a capture**: a `.sh` listing in `# capture: session` mode: `rustc` builds
  `moorc.rs` from `$CH` into the session directory, `./moorc "$CH/x.moor" > x.S`, `python -m rv run x.S`.
  The first session line is always the build, and the text says so. Single-stage demos are `.rs` listings
  with `// capture: args=x.moor`.
- **Tests**: per chapter a Cargo crate under `tests/` (`src/lib.rs` pulls the listings in with `#[path]`;
  clippy -D warnings applies to listing code) for Part I; pytest end to end for ch. 7–8 (build `moorc` with
  `rustc` into `tmp_path`, compile every `.moor` sample, run it with `rv`'s Python API, compare with the
  expected output written in the test). `*_test.c` for Part II and ch. 24/31; pytest + hypothesis elsewhere.
- **Reused Python modules across chapters** (ch. 15 `tm.py` in 16–17; ch. 18 `cdcl.py` in 17 and 20; ch. 25
  `netsim.py` in 26): imported through two unprinted `sys.path` lines above every printed range; tests use a

  ch. 32 replicas 45320–45339. Each server starts and stops inside one capture.
- **Nondeterminism**: threaded and networked listings print only what every run must print (agreement,
  totals, invariants held); counts that vary (litmus outcomes, speed-ups) are in `MEASURED.txt` with a
  *laptop* caption. Interleavings that teach (deadlock, ABA, races) are replayed deterministically by a

# Part I — Compilers and programming languages (Rust)

### Ch. 1 `lexical-analysis` — Lexical Analysis

- **Programme**: M-ASI (lexical analysis by finite automata), A-TLC, S-COMP, L-IT2.

  character.

  minimisation (Y2 `finite-automata`, `regular-languages`); Rust enums/match (Y2).
- **Listings** (`code/bachelor-3/01-lexical-analysis/listings/`): `token.rs` (Token, TokenKind, Span; NORUN,
