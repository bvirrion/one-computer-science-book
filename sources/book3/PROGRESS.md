## For the shared docs

- `\code{...}` doubles a `#` (`\code{#include}` prints `##include`: the argument passes through a macro
  parameter). Write `\texttt{\#include}` (and escape `_` there). A `%` inside `\code{}` starts a comment: use
  `\texttt{\%d}`.
- `gcc -c` of a `.c` given on the link line writes a random `/tmp/ccXXXX.o` name into linker messages: compile
  to an object first in a captured session.
- `-std=c17` hides POSIX `clock_gettime`; time with C11 `timespec_get(&t, TIME_UTC)`.
- gcc 11 folds `x + 1 > x` to 1 even at `-O0`; show the contrast with `-fwrapv`, not with `-O0`/`-O2`.
- UBSan reports each source location once: a loop that overflows twice prints one report.
- Stack addresses (ASan reports, crash depths) depend on the size of the caller's environment, which
  `capture_output.py` passes through: a capture and the `test_code.sh` rerun differed by 48 bytes. Run such
  programs as sessions whose first hidden line re-executes the script with a fixed environment and no
  randomisation: `[ -z "$NORAND" ] && exec env -i NORAND=1 PATH=/usr/bin:/bin setarch "$(uname -m)" -R bash "$0" # hidden`.
- A capture *session* does not get `setarch -R` (only compiled `.c` listings do). For a session whose output
  depends on stack placement (crash depths), a first hidden line re-executes the script without
  randomisation (see the line above for the form that also fixes the environment).
- A crashing command in a session: `{ ./prog; } 2>/dev/null; echo "exit status $?"` hides bash's
  "Segmentation fault" line, which carries a process number.
- LeakSanitizer at `-O0` missed one of the lost blocks (a stale copy of its address kept it ""reachable""); at
  `-O1` the count is exact. A program that LSan reports loses its buffered stdout (LSan exits with `_exit`):
  `fflush(stdout)` before returning.
- glibc's `printf("%s", p)` on a freed block is not intercepted by ASan; read the bytes in user code to be
  reported.
- `\code{}` uses `\detokenize`: write `&`, `{`, `}`, `_` raw inside it (`\&` prints a backslash).
- Ubuntu's gcc defines `_FORTIFY_SOURCE=2` at `-O1`+: `strcpy` into a too-small struct field aborts with
  ""buffer overflow detected"" (exit 134) when optimised, corrupts silently at `-O0`; ASan does not see
  intra-object overflows. Stage the hook at `-O0`.
- `-Wunused-result` is on by default here (glibc `warn_unused_result` on `scanf`/`fread`): a listing that ignores
  the result prints a warning; check the result or pass `cflags=... -Wno-unused-result`.
- `fmemopen` is POSIX, not C17: under `test_code.sh`'s `-std=c17 -Werror` it is undeclared; use `tmpfile()`.
- `\code{}` and `\texttt`: a fixer that turns `\code{\%d}` into `\texttt{\textbackslash{}\%d}` prints a
  backslash; unescape `\%`/`\#` first. A straight quote inside `\texttt` trips check_prose; write `\char34`.
- bytefield's `\bitheader` cannot sit inside a tabular cell, and it overprints a label set just above it.
- `tools/test_code.sh` builds every `*_test.c` it finds, listings/ included: a printed test program in
  listings/ needs its own first line `// test-with: x.c` (paths relative to listings/).
- With `gcc --coverage a.c b.c -o prog` the counter files are named `prog-a.gcda`; compile with `-c` first so
  that `gcov -b a.c` finds `a.gcda`.
- A program stopped by `abort` (failed `assert`) loses what sat in a fully buffered stdout: under capture, only the
  assertion message appears.
- `\code{}` prints `--` as an en dash (lmtt ligature through `\detokenize`): `gcc --coverage`, `ls --help`,
  `rw-r--r--` came out wrong. Write `\texttt{gcc -{}-{}coverage}`. Affects every book that uses `\code`.
- A session that shows a refused shell operation prints `~/session.sh: line N:`; run it as `bash -c '...'` to get
  `bash: line 1:` instead.
- Python under `git bisect`/checkout loops: a stale `__pycache__` can survive a checkout (same size, same second), so
  a good commit tests bad. Set `PYTHONDONTWRITEBYTECODE=1` in sessions and tests.
- Git sessions: export `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null`, author/committer name, e-mail and
  dates; `git init --bare -b main` too, or the clone has no checkout.
- `NORUN.txt` lives in `listings/`, not in the chapter folder (a misplaced one is silently ignored and the
  modules are run, writing stray outputs).
- Labels of methods are `met:` (CONTRIBUTING), not `meth:`; chapters 5--9 were renamed.
- TikZ: a style named `x` (or `y`) collides with the coordinate keys (`/tikz/x requires a value`); and do not

- After the shared `\omoutput[ranges]` fix (`lastline=`), a range given as a single number (`[3-4,6,10]`, `[2]`)
